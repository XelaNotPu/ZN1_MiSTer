# Raizing / Eighting ZN-1 sound board (Brave Blade music)

The Raizing ZN-1 boards (RA9701 SUB, PS9805) carry a second sound system next
to the PlayStation SPU: a 12 MHz MC68000 running its own program, a Yamaha
YMF271-F "OPX" at 16.9344 MHz with a 4 MiB sample ROM, and an 8-bit command
latch written by the PSX. MAME models it in `src/mame/sony/zn.cpp`
(`raizing_zn_state`) and `src/devices/sound/ymf271.cpp`; this directory is the
FPGA implementation, ported from the Brave Blade fork and wrapped by `rtl/zn_ext_audio.sv`
(RBF `XNZN1RZ`, docs/AUDIO_RAIZING_YMF271.md). It runs only when the MRA selects audio
board `10` (index 1, byte 1) and supplies both sound ROMs (index 6 and 7).

| File | Content |
|---|---|
| `raizing_snd.sv` | Board: fx68k, clock enables, 16 KiB work RAM, 4 KiB program-ROM line cache, latch + IRQ2, YMF271, SDRAM line-port arbiter |
| `ymf271.sv` | YMF271 engine (FM 4-op / 2x2-op / 3-op + PCM, envelopes, LFO, timers, status) |
| `ymf_regram.sv` | 64 x 32 byte-enable RAM (slot register file, 6 instances) |
| `ymf_*.hex` | ROM tables generated by `sim/model/gen_tables.cpp` from MAME's formulas |

## Bus contract (measured in MAME 0.289, `sim/mame/bbtrace.lua`)

* PSX `SH 0x1FB00000` — sound command in bits 7:0 (latched, never cleared).
* PSX `SH 0x1FB00004` — immediately after, asserts 68000 IRQ2 (`HOLD_LINE`:
  stays asserted until the interrupt acknowledge). 23 commands in 150 s of
  attract + game start; e.g. `7F`, `1F` at boot, `08` = attract music at 11.1 s.
* 68000 IRQ2 autovector (vector 26, `0x68` → handler `0x8A6`) reads the latch
  as a word at `0x180008` (low byte) about 17 µs after the PSX write, then
  writes `0x180000/4/6` (acknowledge strobes; unmapped in MAME, ignored here).
* YMF271: word writes to `0x100000 + 2*reg`, data on D7..D0; every data write
  is followed by a busy poll (`btst #7` on status 0). MAME never reports busy,
  and neither does this core (its 16-entry write queue drains faster than the
  68000 can write). Tempo comes from polling the timer A/B flags in status 0.
* Program: `0x000000-0x07FFFF` (the upper half of the 1 MiB region is 0xFF).
  RAM actually used: `0x080000-0x083FEE` (stack at `0x83FF0`); 16 KiB is
  implemented and mirrored over `0x080000-0x0FFFFF`.
* Sample ROM addresses used: `0x0466A2-0x32F7CA`.
* YMF271 features exercised by Brave Blade: 9 groups of 4-op FM (sine only,
  algorithms 3/6/12, feedback), 3 groups of 4-voice PCM (8-bit, fs 0/1),
  timers A and B, end-status flags. LFO registers are written with PMS=AMS=0.

## Memory layout

| SDRAM | Content | MRA |
|---|---|---|
| `0x1800000-0x18FFFFF` | 68000 program, 1 MiB interleaved (`spu0u049` even, `spu1u412` odd bytes) | index 6 |
| `0x1C00000-0x1FFFFFF` | YMF271 sample ROM (`ra-bbl_rom2.336`) | index 7 |

This is banked-ROM bank 2, which Brave Blade never selects (bank-select
writes seen: 0 and 1 only), so it fits a standard 32 MiB module. SDRAM
channel 3 (download/cheat port) is shared: downloads first, then the sound
board, which reads 16-byte lines (burst of 8 words, same command sequence as
channel 1's cache fills). A channel-3 request that waited ≥ 64 SDRAM clocks
is served next, so heavy PSX traffic cannot starve the music. The MRA byte
streams were checked byte-for-byte against MAME's logical `audiocpu` and `ymf`
regions (SHA-1 `85591745…` and `d955a70a…`).

## YMF271 implementation

* `clk_1x` (33.8688 MHz) is exactly 2x the chip clock, so one 44.1 kHz sample is
  768 clocks. Per sample the engine walks the 12 groups; each group runs a small
  op program selected by (sync mode, algorithm). One 18x18 multiplier is
  time-shared; everything else is shift/add (the PSX core uses 108 of 112 DSP
  blocks). Worst case measured over 150 s of Brave Blade: 584 clocks/sample
  (60-clock fetch latency: 656).
* Envelope rates are latched at key-on (as MAME does); key-on/off are applied on
  the slot's next visit (< 1 sample).
* PCM: each PCM slot has an even/odd pair of 16-byte line buffers and prefetches
  the next line, so sequential playback does not wait on SDRAM.
* Output = mix/4, saturated, like MAME's `put_int(…, 32768 << 2)`.
* Mixed with the SPU as `SPU * 45/64 + YMF * 2` (MAME's 0.35 : 1.0 balance,
  +6 dB so the loudest passages peak around -3 dBFS).
* Not implemented (also missing or TODO in MAME): PFM, detune, alternate loop,
  Acc-On, EXT out, external-memory read-back, PCM on groups that have no PCM
  address registers. LFO pitch modulation uses a linear approximation of
  MAME's `pow()` (unused by Brave Blade).

## Verification

* `sim/model/ymf_mame.h` (MAME port) vs MAME's own `-wavwrite` output:
  correlation 0.998 (residual = SPU effects + resampling).
* `ymf_fx.h` (fixed-point model) vs the MAME port over 150 s of captured
  register writes: 99.98 % of samples identical, RMS difference 0.1 LSB
  (MAME gates a group per buffer, the hardware per sample).
* `ymf271.sv` vs `ymf_fx.h`: bit-exact over the full 150 s capture
  (6.6 M stereo samples), with a 24- and a 60-clock memory latency.
* `raizing_snd.sv` running the real sound program with the PSX commands at the
  MAME timestamps (120 s: boot, attract, coin, start, first stage):
  177,684 YMF271 writes vs MAME's 177,696; the write count after each of the
  23 PSX commands matches MAME (typically within ±2); the first 4,100 writes are
  identical in content and order (≤ 85 µs offset). Output level matches the
  MAME-log-driven model within 1-4 % RMS; waveform correlation after alignment
  0.90 (attract music) to 0.98 (game start).
* Known deviation: the driver services timer ticks by polling, so when it is busy
  (e.g. the 70 ms burst that starts a song) two ticks can merge. Program-ROM
  cache misses make this core reach that point ~0.3 ms later than MAME's
  zero-latency ROM, so a song can start one timer tick (8 ms) later than in
  MAME. Tempo is unaffected.

## Limitations

* Save states do not include the sound board (music may be wrong after a load).
* Other Raizing titles need their own ROM entries and a check of RAM size,
  program size and unused SDRAM space (Bloody Roar 2 fills all 24 MiB of banks).
